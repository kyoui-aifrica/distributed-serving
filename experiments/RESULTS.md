# H100 2장 병렬화 실습 결과

## 1. 실습 환경

| 항목 | 값 |
| --- | --- |
| GPU | NVIDIA H100 80GB HBM3 2장, NVLink 연결 (`NV18`) |
| 드라이버 | 595.58.03 (CUDA 13.2) |
| vLLM | 0.34.0 |
| torch | 2.14.0+cu130 |

## 2. 실험 1. 1장으로 서빙할 수 있는 모델 (Qwen3-14B)

| ID | ITL, 동시 요청 1 (ms) | TTFT, 동시 요청 128 (ms) | 출력 처리량, 동시 요청 128 (tok/s) |
| --- | --- | --- | --- |
| `14b-1gpu` | 11.3 | 1403.7 | 3039.9 |
| `14b-dp2` | 11.2 | 1128.0 | 4755.5 |
| `14b-tp2` | 6.9 | 853.9 | 5046.7 |
| `14b-pp2` | 11.3 | 1094.3 | 4284.5 |

- DP는 출력 처리량이 1장보다 1.56배 높아 예상과 일치
- TP는 ITL이 1장보다 39% 짧아 예상과 일치
- PP는 출력 처리량이 1장보다 1.41배 높아 예상과 일치
- 예상과 달리 동시 요청 128의 출력 처리량은 TP가 DP보다 6% 높음
  - DP는 GPU마다 요청 64개를 처리하면서 가중치 전체를 읽어 메모리 대역폭 병목 발생
  - TP는 GPU마다 가중치 절반만 읽고 요청 128개를 한꺼번에 처리해 메모리 대역폭 병목 감소

## 3. 실험 2. 2장으로 서빙해야 하는 모델 (Qwen2.5-72B-Instruct)

| ID | ITL, 동시 요청 1 (ms) | TTFT, 동시 요청 8 (ms) | 출력 처리량, 동시 요청 8 (tok/s) |
| --- | --- | --- | --- |
| `72b-tp2` | 27.7 | 1008.1 | 248.2 |
| `72b-pp2` | 50.0 | 1566.3 | 138.5 |

- TP는 ITL이 PP보다 45% 짧아 예상과 일치

## 4. 실험 3. MoE 모델 (Qwen3-30B-A3B)

| ID | ITL, 동시 요청 1 (ms) | TTFT, 동시 요청 128 (ms) | 출력 처리량, 동시 요청 128 (tok/s) |
| --- | --- | --- | --- |
| `moe-tp2` | 4.0 | 361.3 | 6290.2 |
| `moe-ep2` | 5.7 | 620.4 | 5975.8 |

- EP는 출력 처리량이 TP보다 5% 낮아 예상과 다름
- 동시 요청 32에서만 EP의 출력 처리량이 TP보다 6% 높음
- 예상과 다른 이유
  - 어텐션 가중치는 모델의 약 3%라 어텐션 통신을 없앤 이득이 작음
  - EP는 MoE 레이어마다 토큰을 담당 GPU로 보냈다가 다시 모으는 통신이 필요해, TP의 all-reduce보다 통신 비용이 큼
  - DP 엔진 2개가 스텝을 맞춰 돌아서, 한 엔진이 프리필하는 동안 다른 엔진의 디코드도 기다림
  - 토큰마다 고르는 전문가 8개가 두 GPU에 고르게 나뉘지 않아 한 GPU가 평균 5개를 맡고, 이 GPU를 기다리느라 동시 요청 1의 ITL도 TP보다 김

## 5. 실무 결론

| 상황 | 고를 기법과 이유 |
| --- | --- |
| 1장으로 서빙할 수 있는 모델, 처리량이 목표 | DP나 TP, DP는 출력 처리량이 1장보다 1.56배 높고 이번 측정에서는 TP가 DP보다 6% 더 높음 |
| 1장으로 서빙할 수 있는 모델, 지연이 목표 | TP, ITL이 1장보다 39% 짧음 |
| 2장으로 서빙해야 하는 dense 모델 | TP, ITL이 PP보다 45% 짧고 KV 캐시도 더 큼 |
| MoE 모델 | TP, 2장에서는 EP보다 출력 처리량이 5% 높고 ITL이 29% 짧음 |
